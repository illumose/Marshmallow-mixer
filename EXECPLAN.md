# Private mixer hardening (review only)

The source mixer accepts arbitrary URLs without authentication, follows redirects, performs unbounded downloads, runs subprocesses without deadlines and retains voice/music/output files. Preserve its JSON `voice_url`/`music_url` API and audible behavior (7-second delay, 10% music, 4-second tail, 3-second fade), but prepare a private prototype-safe implementation before sending any group audio.

Scope: dedicated bearer token; exact private voice origin/key/token path; reviewed music and redirect hostnames; public DNS verification with IP-pinned TLS; no voice redirects; bounded bodies/downloads/concurrency/deadlines; restricted media demuxers/protocols; fixed content-free failures; request-scoped files removed after response, disconnect or errors. No storage admin key or BFF callback secret enters this service. Dependencies are pinned; original live mixer and workflows remain untouched.

Verification: synthetic authorization/URL/DNS/redirect/size/error/concurrency/cleanup tests, including response-send failure; real FFmpeg synthetic WAV-to-MP3 mix and duration/cleanup. No real external downloads or private recordings. Local Python 3.12; CI targets Docker's Python 3.11. Run the focused service suite once after implementation, then only failed/changed checks.

Recovery: this is a draft PR, not deployment. Keep the current native guards/workers paused. Roll back code using the original commit if needed; no schema changes. A separately reviewed target and dedicated credential binding are required before using the hardened path; do not reuse BFF callback credentials or silently break the original service. Exact Dropbox redirect hosts, hosted identity, proxy/logging policy, real retention and full-chain timing remain activation gates. Auth/URL/cleanup tests must pass before requesting deployment approval.

Results: 18 focused tests pass locally on Python 3.12, including real FFmpeg WAV-to-MP3 output/timing, body/URL/DNS/redirect/stream limits, IP-pinned hostname-verified TLS, authenticated readiness with no media calls, capacity held through response completion, error/disconnect cleanup and deferred cleanup after cancellation during a worker thread. The hash-locked 14-package dependency set installs successfully and a fresh PyPA pip-audit scan reports no known vulnerabilities. This does not assess container OS libraries or certify future advisory state. CI builds and runs the real non-root Python 3.11 image with network disabled, read-only root and temporary filesystem; that result remains pending until the review run completes.
